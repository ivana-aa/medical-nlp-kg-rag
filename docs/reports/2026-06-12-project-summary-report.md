# 中文医疗 NLP 项目总结报告

## 一、项目概述

本项目围绕中文医疗文本处理构建了一个完整的 NLP 工程示例，核心目标是实现医疗实体识别、医学知识组织和基于证据的医疗问答。系统包含三个主要能力：

1. 中文医疗命名实体识别：从中文医学文本中识别疾病、症状、药物、检查、手术、身体部位和医学检验指标等实体。
2. 医学知识图谱：将医学关系数据转换为结构化三元组，支持实体查询、关系检索和图谱证据展示。
3. 医疗问答 RAG / Graph-RAG：从本地医学知识库和医学知识图谱中检索证据，生成带来源说明和医疗风险提示的回答。

项目使用公开数据源或人工 demo 数据，不使用真实患者病历，不采集患者隐私信息。所有医疗问答结果均定位为学习和科普参考，不能替代医生诊断或治疗建议。

## 二、技术架构

项目采用标准 Python 工程结构，主要技术栈如下：

| 模块 | 技术选型 | 作用 |
| --- | --- | --- |
| NER | PyTorch、Transformers、MacBERT、BIO 标注 | 中文医疗实体识别训练、评估和推理 |
| RAG | sentence-transformers、FAISS、BM25、NumPy fallback | 本地医学文本向量化、混合检索和证据召回 |
| KG | pandas、NetworkX、CSV 三元组 | 医学知识图谱构建和图谱证据检索 |
| Web UI | Streamlit | 项目总览、NER、RAG、Graph-RAG 页面展示 |
| 测试 | unittest | 核心数据处理、后处理和检索逻辑验证 |

整体流程如下：

```text
公开医学数据 / demo 数据
        ↓
数据清洗与格式转换
        ↓
NER BIO 数据集 / 本地知识库 / 医学三元组
        ↓
MacBERT NER 训练与推理
        ↓
向量库构建 + BM25 混合检索 + 知识图谱检索
        ↓
RAG / Graph-RAG 医疗问答
        ↓
Streamlit Web 展示
```

## 三、数据来源与合规设计

项目优先使用公开、可追溯的数据来源。当前项目中已经接入或说明的数据源包括：

| 数据来源 | 当前用途 |
| --- | --- |
| CMeEE / CBLUE | 用于中文医疗实体识别任务，支持从 OpenDataLab / OpenXLab 下载并转换为 BIO 格式 |
| CMeIE | 用于医学关系抽取数据转换，构建医学知识图谱三元组 |
| MedQuAD | 用于扩展英文医疗问答样例，支持导入本地 RAG 知识库 |
| PMC Open Access Subset | 作为后续医学文献 RAG 的公开数据来源说明 |
| Europe PMC Open Access | 作为后续开放获取医学文献补充来源说明 |
| 人工 demo 医学科普文本 | 用于无外部数据时快速跑通 NER、RAG 和 Web 演示 |

合规边界：

- 不使用非法爬取的真实病历。
- 不使用包含患者姓名、手机号、身份证号、住址、住院号等隐私字段的数据。
- 对 PMC、Europe PMC 等论文来源保留许可证检查要求，不默认抓取非开放许可全文。
- 大型原始数据和模型运行产物不提交到 GitHub 源码仓库。

## 四、NER 模块完成情况

NER 模块使用 `hfl/chinese-macbert-base` 作为默认中文预训练模型，采用 token classification 方式完成中文医疗实体识别。数据格式使用 BIO 标注，每个字符对应一个标签。

已完成能力：

- 支持 demo 数据生成。
- 支持 CMeEE 数据转换为 BIO。
- 支持训练、验证、测试。
- 支持 Precision、Recall、F1 指标输出。
- 支持训练历史和评估报告保存。
- 支持模型推理接口。
- 支持词典后处理，用于提升展示稳定性。
- 支持错误分析脚本。

当前 active checkpoint 的测试集示例指标如下：

| 指标 | 数值 |
| --- | --- |
| Precision | 0.5574 |
| Recall | 0.6293 |
| F1 | 0.5911 |

分实体类型表现摘要：

| 实体类型 | F1 |
| --- | --- |
| BODY | 0.6001 |
| DISEASE | 0.6922 |
| DRUG | 0.7847 |
| EXAM | 0.4816 |
| SURGERY | 0.5726 |
| SYMPTOM | 0.3972 |
| TEST | 0.5008 |

该结果用于说明完整训练和评估链路已经跑通，不代表临床级模型效果。后续若使用完整 CMeEE 数据集、增加训练轮次并进行系统调参，模型效果仍有提升空间。

## 五、RAG 问答模块完成情况

RAG 模块支持从本地 `txt`、`md`、`csv`、`json` 文件加载医学文本，经过分块、向量化、向量库构建和检索后生成回答。

已完成能力：

- 支持多格式医学文本加载。
- 支持文本分块和 overlap。
- 支持 `sentence-transformers` 中文向量模型。
- 支持 FAISS 向量库。
- 支持 FAISS 不可用时使用 NumPy 检索降级。
- 支持 BM25 与向量检索混合召回。
- 支持证据片段、来源文件和相似度展示。
- 所有回答均包含医疗风险提示。

当前本地知识库状态：

| 项目 | 数量 |
| --- | --- |
| 知识库文件 | 5 |
| 检索分块 | 142 |

知识库文件包括中文 demo 医学科普文本、检验指标 CSV、医学 FAQ JSON、MedQuAD QA 样例和公开医学来源说明文件。

## 六、医学知识图谱与 Graph-RAG 完成情况

项目增加了轻量医学知识图谱模块，用于把结构化关系作为 RAG 的补充证据。

已完成能力：

- 支持医学三元组 CSV 格式。
- 支持 CMeIE 风格 JSON / JSONL 数据转换为 KG CSV。
- 支持关系过滤和 review-friendly 子图构建。
- 支持 NetworkX 加载和实体邻接关系查询。
- 支持 Graph-RAG 页面展示文本证据与图谱证据。
- 支持 NER 辅助候选关系生成。

当前 demo 医学图谱文件 `data/medical_kg/medical_kg.csv` 包含 21 行记录，其中 1 行为表头，20 行为三元组样例。

Graph-RAG 的核心价值在于：回答不只依赖文本相似度检索，还能额外展示结构化关系证据，使系统更适合解释“疾病-症状-检查-药物”这类医学知识关系。

## 七、Web 展示与交互

项目使用 Streamlit 构建本地 Web 页面，启动命令为：

```powershell
streamlit run src\app\streamlit_app.py
```

页面包含：

1. 项目总览：展示 NER 模型、向量库、知识库、检索分块和公开数据源状态。
2. 医疗问答 RAG：输入问题后展示回答、证据片段、来源和风险提示。
3. 医疗 NER：输入中文医疗文本后展示实体表格、彩色标签和实体类型统计。
4. 医学知识图谱与 Graph-RAG：展示图谱三元组、文本证据和融合回答。

典型演示问题：

```text
高血压患者平时需要注意什么？
糖尿病患者为什么需要监测血糖？
肺炎有哪些症状，需要做什么检查？
What is Adult Acute Lymphoblastic Leukemia?
```

典型 NER 输入：

```text
患者出现头痛和胸闷，医生建议进行血压检查，并考虑使用硝苯地平。
```

## 九、测试与验证

项目包含 `tests/` 单元测试，覆盖以下内容：

测试命令：

```powershell

```

此前完整测试结果为 32 个测试通过，说明核心数据处理、检索和后处理逻辑具备基本回归验证。

## 十、项目亮点

1. 工程链路完整：从数据准备、模型训练、评估、向量库构建到 Web 展示均已打通。
2. 数据合规意识明确：不使用真实患者隐私数据，公开数据源和许可证边界写入 README。
3. 模块覆盖面较完整：同时包含 NER、RAG、KG 和 Graph-RAG，不只是单一模型训练脚本。
4. 支持离线运行：默认不依赖外部大模型 API，RAG 使用本地证据生成模板式回答。
5. 具备发布形态：源码仓库与 Release 大文件包分离，适合他人阅读源码或下载完整演示包。
6. 具备测试基础：核心模块有单元测试，便于后续迭代时控制回归风险。

## 十一、当前不足

1. active NER 模型仍属于演示级 checkpoint，F1 约 0.59，距离高质量医疗 NER 仍有差距。
2. RAG 默认使用模板式回答，语言生成能力不如接入专业大模型后的效果。
3. 中文医疗知识库规模较小，当前更适合展示流程，不适合真实医学问答覆盖。
4. CMeEE 存在嵌套实体，普通 BIO 标注无法完整表达所有重叠实体。
5. 医学知识图谱 schema 较轻量，尚未加入实体标准化、置信度、许可证字段和审核状态。
6. 当前系统没有面向生产环境的权限控制、审计日志、隐私脱敏和专家审核流程。

## 十二、后续优化方向

短期优化：

- 使用完整 CMeEE 数据集训练，增加 epoch、batch size 和学习率搜索。
- 增加 CRF、GlobalPointer 或 span-based NER 模型，对比 BIO token classification。
- 扩充中文医学知识库，提高 RAG 对中文问题的覆盖率。
- 加入 cross-encoder reranker，提高证据排序质量。

中期优化：

- 接入本地大模型或可配置 LLM API，增强回答组织能力。
- 加入实体标准化，将疾病、药物、检查映射到标准医学术语库。
- 扩展 CMeIE 关系抽取与图谱构建流程。
- 增加 RAG 自动评测，评估召回率、忠实性和引用一致性。

长期优化：

- 建立医学专家审核流程。
- 支持多数据源许可证追踪和引用审计。
- 增加隐私脱敏、输入安全过滤和高风险问题分级。
- 将项目扩展为可部署的医疗知识助手原型服务。

## 十三、结论

本项目已经从最初的教学 demo 升级为结构较完整的中文医疗 NLP 工程项目。系统具备中文医疗 NER、医学知识图谱、RAG 检索问答、Graph-RAG 融合问答、Streamlit 可视化展示、GitHub 公开发布和 Release 完整演示包等能力。

从工程角度看，项目的主要价值不在于单个模型指标，而在于完整呈现了医疗 NLP 项目从公开数据接入、模型训练、知识库构建、证据检索、问答生成到 Web 展示的端到端流程。后续若继续扩充真实公开医学数据、优化模型结构和增强 RAG 评测，该项目可以进一步发展为更接近实际应用的医学知识问答系统原型。

## 十四、医疗安全声明

本项目输出内容仅供学习、研究和技术演示使用，不构成医疗诊断、治疗方案或用药建议。任何涉及疾病诊断、治疗、用药调整、急症处理的问题，都应咨询具备资质的医生或正规医疗机构。
